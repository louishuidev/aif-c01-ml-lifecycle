Top 5 必記

  1. Amazon SageMaker — 幾乎每個階段都有（核心中的核心）
  2. Amazon S3 — 訓練資料 & 模型 artifact 儲存

  4. AWS Glue — 資料 ETL 與 Data Catalog

快速記憶提示

  • SageMaker = 一站式解決方案（訓練、調參、部署、監控、Pipeline 全包）
  • S3 + ECR = 資料與容器的基礎組合
  • Glue 家族 = 資料準備主角
  • Bedrock = 生成式 AI 的快速起點（foundation model）
  • CloudWatch = 監控結果的告警中心

Lesson 1: ML Pipelines and Business Goal

ML Pipeline Overview
  • 一系列相互連接的步驟，從業務目標開始，結束於運作已部署的模型。
  • 階段：定義問題 → 收集與準備資料 → 訓練模型 → 部署 → 監控。
  • 反複性質；模型動態，需用新資料重新訓練。
  • 較好的觀點：Lifecycle（部署後仍可能重複部分或全部流程）。
Starting with the Business Goal
  • 清楚定義問題與可量化業務價值。
  • 定義具體 success criteria。
  • 對齊利益相關者。
  • 評估組織能力與生產路徑。
  • 判斷 ML 是否最佳方案（比較準確度、成本、可伸縮性）。
  • 確保有足夠高質量訓練資料。
  • 從最簡單解決方案開始，必要時才增加複雜度。
  • 做成本效益分析。
AWS AI/ML Service Options
  1. Fully hosted AI services（例：Amazon Comprehend）
  2. Start with existing models（Bedrock foundation models / SageMaker pre-trained）
  3. Train from scratch（最難、最貴、責任最高）

SageMaker JumpStart：預訓練 foundation 與 task-specific 模型，支援 transfer learning。

Lesson 2: Collecting and Processing Training Data

Data Collection & Preparation
  • 確認資料來源、儲存位置、streaming vs batch。
  • 設置可重複的 ETL 流程。
  • 標註資料常常是最耗時的步驟。
  • 資料準備包含 pre-processing 與 feature engineering。
  • 處理缺失值、異常值、PII。
Data Splitting & Features
  • 常見分割：~80% training / ~10% evaluation / ~10% test
  • 只保留對推論有用的 features，減少記憶體與計算需求。
Key AWS Services
  • AWS Glue：完全托管 ETL + Data Catalog（只存 metadata）
  • Glue DataBrew：視覺化無程式碼資料準備（250+ 轉換）
  • SageMaker Ground Truth：高質量標註（active learning + 人工）
  • SageMaker Canvas：視覺化準備與 feature engineering
  • SageMaker Feature Store：集中管理與重用 features

Lesson 3: Training, Tuning, and Evaluating

Training Process
  • 反複更新參數（weights），使推論接近期望輸出。
  • 多個算法與設定應平行實驗。
  • Hyperparameters：訓練前由資料科學家設定（例：layers、nodes）。
SageMaker Training & Experiments
  • 建立 training job：指定 S3 資料、計算資源、輸出 S3、ECR container image、hyperparameters。
  • SageMaker Experiments：比較不同訓練運行。
  • Automatic Model Tuning (AMT)：自動尋找最佳 hyperparameter 組合。

Lesson 4: Deploying the Model

Inference Options
  • Batch：大量、可等待（最省成本）
  • Real-time：即時回應（REST API）
SageMaker Inference Options
  1. Batch Transform：離線、大資料集
  2. Asynchronous：排隊、大 payload，空閒可縮到 0
  3. Serverless：Lambda，按使用量付費
  4. Real-time：持久 endpoint，持續流量

低運維負擔：用 SageMaker 管理 endpoint（指向 S3 + ECR）。

Lesson 5: Monitoring and MLOps

Monitoring & Drift
  • 監控系統：捕捉資料 → 比較訓練集 → 規則偵測 → 告警。
  • Data drift：資料分佈變化
  • Concept drift：目標變數特性變化
  • SageMaker Model Monitor + CloudWatch 告警可觸發再訓練。
MLOps & Pipelines
  • 套用軟體工程最佳實踐：自動化、版本控制、監控、自動再訓練。
  • 好處：生產力、可重複性、可靠性、審計性、資料與模型品質。
  • SageMaker Pipelines：可重現的 ML pipeline 編排。

Lesson 6: MLOps Services & Classification Metrics

Other Services
  • SageMaker Feature Store / Model Registry
  • AWS Step Functions（視覺化工作流）
  • Amazon MWAA（管理式 Apache Airflow）
Confusion Matrix & Metrics
  • TP / TN / FP / FN
  • Accuracy = (TP+TN)/Total（不平衡資料集時不可靠）
  • Precision = TP/(TP+FP) — 減少 false positives
  • Recall = TP/(TP+FN) — 減少 false negatives
  • F1 Score：Precision 與 Recall 的平衡

Lesson 7: More Metrics & Business Metrics

Additional Metrics
  • False Positive Rate, True Negative Rate
  • AUC / ROC：跨所有閾值的整體表現（0.5 = 隨機，1 = 完美）
  • 回歸：MSE、RMSE（單位一致、易解釋）、MAE
Business Metrics
  • 定義可量化成功標準（成本降低、銷售增長、客戶回饋等）。
  • 上線後比較實際結果與目標。
  • 計算 ROI，使用 cost allocation tags + Cost Explorer 追蹤費用。

Key Takeaways

  • 始終從清楚的業務目標與 success criteria 開始。
  • 優先選擇最簡單可行方案（hosted AI → transfer learning → train from scratch）。
  • 資料品質、標註與 feature engineering 非常關鍵。
  • 大量使用 SageMaker（訓練、實驗、調參、部署、監控、Pipeline）。
  • 持續監控 drift + MLOps 自動化是生產環境的基礎。
  • 根據業務影響選擇指標（precision vs recall 等）。
  • 同時追蹤技術指標與業務指標（含成本與 ROI）。
